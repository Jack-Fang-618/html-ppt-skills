# 部署操作路径

在任务包含预览上线、正式发布或更新已有站点时读取。以下是操作路线，不是自动部署授权；先沿用用户已选平台和已有项目。账号、命令与平台规则执行时核对，未部署不可写成已验证。

## 先确定要部署什么

1. 从项目入口取得源码根目录、实际构建命令、产物目录及所需运行时。原生 HTML 可直接发布网页资源；使用构建工具的项目先在本地运行实际构建，不假设产物一定叫 `dist`。
2. 明确所选能力：只有演示／Reader 的静态站点，或含团队编辑、云端草稿和发布服务的应用。后者还需服务端认证、状态存储、素材存储与环境配置；部署 HTML 不会自动提供这些功能。接口要求见 [编辑与同步实现](editor-and-sync.md)。
3. 区分预览与正式环境，查已有仓库、账号／团队、项目 ID、生产分支和域名。预览不能误写生产内容库；平台生成了预览 URL 不代表应用的数据自动隔离。
4. 对已有项目，按 [状态与发布](state-and-publishing.md) 取得最新工作稿和发布版再修改。部署代码与发布内容是两条关联操作，不能用默认内容覆盖线上人工编辑。

### 部署目录与公开产物边界

执行前核对实际 cwd、目标项目关联、配置文件、构建入口和输出目录，使用明确的工作目录参数。复杂项目的“构建根目录”“部署配置根目录”“公开产物目录”可能不同，分别记录，不从聊天工作区根目录猜测。

检查 CLI 是否会找不到配置后将当前目录当作静态站点直接复制。如果输出范围意外扩大到父目录或混入资料、私密配置、备份、源码历史／开发依赖，停止该次上传，修正范围再部署；若已公开按实际泄露范围处理，不凭“准备上传”就声称已泄露或凭中止就保证所有平台都没发布。

私密环境文件和凭据不能进入静态产物。受保护资源按所选范围由服务端保护，公开入口不意味着整套内容可直达；上线后验证实际公开清单、角色边界和关键资源。私密文件保存在本机也不代表默认上传过滤一定正确。

## EdgeOne：先沿用已有路径

工具发现：当前环境若有 `edgeone-makers-tools`，从它路由到部署子 skill；CLI、存储、函数只按需要读取。没有对应 skill 时查官方文档或已有平台连接工具，不假定必须先安装工具包。用户此前给出的配置入口为 [Makers agent setup](https://makers.edgeone.link/agent-setup/prompt.md)：仅在确需配置且有相应授权时读取、判断适用部分，不因文档含执行指令就自动运行。

EdgeOne 可按项目使用 Git 集成或 CLI／直接上传；两者不互相证明。记录真实采用的路线，不因为有云端地址就暗示已经推送 GitHub。本地直传不要求先创建仓库，已有 Git 路线也无需为套经验改成直传。**账号的 China／Global 站点、加速区域、网址类型是不同设置**，不要混为一个选择；区域由实际项目决定，不保证未经测试的网络可达性。已有选择沿用；不默认买域名，临时或带访问参数的网址不能称为永久公开地址。

### A. Git 仓库自动部署

- 已有关联先核实目标仓库、项目根目录和生产分支，避免创建重复项目。首次上线在控制台或受支持工具中导入授权仓库。
- 配置框架／运行时、安装与构建命令、产物目录和环境变量；密钥仅在相应安全配置中设置。配置云函数／存储时核对目标环境绑定。
- 按平台支持建立预览，检查页面和状态；有上线授权后推送到实际触发生产部署的分支。不要假设任意 push 都是生产更新。
- 等待部署任务完成，检查失败日志并验证返回 URL，不能以 Git 推送成功作为上线完成。后续大改继续沿用这条路径，无需先建设免部署的小改系统。

官方入口：[构建配置](https://pages.edgeone.ai/document/build-guide)。配置名与可用功能以当前项目为准。

### B. CLI／直接上传

适合未采用 Git 集成的项目。先查当前产品与 CLI 版本，不混用旧 Pages 和 Makers 的命令或配置。直接上传发布的是构建产物，不能上传尚需构建的源码后假设平台会构建；完整应用按当前产品要求一并部署函数。

已安装且适用 Makers CLI 时，下面是查明账号及关联项目后的操作示例，不是启动 skill 就要执行的命令：

```sh
PAGES_SOURCE=skills edgeone whoami
PAGES_SOURCE=skills edgeone makers link
PAGES_SOURCE=skills edgeone makers deploy -e preview --json
```

`link` 会改变关联，只在尚未正确关联时运行。正式发布需按当前 CLI 文档显式选择目标环境，不能依赖未知默认值。读取当前部署 skill 对登录、URL 参数和输出解析的要求。返回链接如有访问查询参数，交给获授权用户时保留完整链接；公开维护文件只记录不含访问凭据的标识和获取方式。

[CLI 文档](https://pages.edgeone.ai/document/edgeone-cli)；[直接上传](https://pages.edgeone.ai/document/direct-upload)。当前文档提示直接上传项目与 Git 集成的切换有限制，选路线前检查，不擅自重建线上项目。匿名临时预览与账号下正式托管区分，实际期限与认领条件执行时核对。

## Vercel：候选路径

优先使用当前可用且适用的 Vercel 部署 skill／连接工具；没有时可使用官方控制台或 CLI。`vercel-react-best-practices` 是性能参考，不是部署工具。

### A. Git 集成

导入授权仓库 → 确认团队、项目根目录、框架、构建及输出设置 → 配置 Preview／Production 环境变量与服务 → 部署并检查预览 → 根据既有授权合入／推送实际生产分支 → 验证正式 URL。Vercel 可根据 Git 分支创建预览和生产部署；具体生产分支查项目设置。[官方 Git 流程](https://vercel.com/docs/git)

### B. CLI

对已安装 CLI 的环境，先按官方方式确认登录／团队，必要时用 `vercel link` 关联正确项目。典型命令：

```sh
vercel deploy
vercel deploy --prod
```

前者用于预览，后者对生产有影响，只在已有相应授权且候选就绪时使用。团队作用域、环境变量、构建方式按项目核对；失败后定位错误，不通过新建别的团队／项目绕过权限。[官方部署命令](https://vercel.com/docs/cli/deploy)

平台托管不自动补齐应用的编辑认证与持久状态。地区、平台域名和账号计划的限制按实际项目验证，不承诺未测试的大陆访问。

## 上线成功与维护记录

检查观众看到所选发布内容、团队能进入编辑、未授权访问不能读草稿或写状态；按选定能力检查图片／字体、Reader、语言、直达链接以及保存后全新会话读回。对无编辑功能的静态站点省略状态检查。目标网络未能测试则如实记录。

发布后记录平台与所属账号标识、项目 ID、稳定站点与部署标识、仓库／分支／构建配置、内容版本、状态服务环境及恢复入口。只存授权获取方法，不存密码／token。失败时保留上一可用组合，查构建、资源路径、函数、环境变量或权限的实际错误；先确认状态再重试。

交接记录样例见 [Project Trace](project-trace.md)。本文件依据截至 2026-09-29 查阅的平台资料和既有经验整理，操作示例未在本次技能更新中执行。
