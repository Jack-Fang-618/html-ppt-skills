# 多格式交付的制作方法

需要制作文件时读取；交付取舍与验收标准见 [验收与交付](review-and-delivery.md)。这里提供通用实现路线，不依赖任何旧报告脚本，也未附带转换器。先发现当前可用的 PDF／演示文稿工具，按其说明选方法。

## 默认输出范围

HTML 为主展示不意味着 PPTX／PDF 需要复制全部网页模式。用户要求普通演示文件时，默认只输出 Presentation 主展示，不包含 Reader、Editor、登录页、应用工具栏或网页导航。即使 HTML 有 Reader，也不自动生成细读文件；用户需要阅读材料时，再选择备注、附录或独立细读 PDF。必要的来源标注仍保留，承担核心解释的交互按下文转成静态内容。

本技能提供制作方法，agent 按项目使用相应工具生成并验收文件；没有实现并验证网页导出按钮时，不能声称支持一键导出。可编辑 PPTX 另按实际对象和编辑目标检查，不以截图文件代替所承诺的编辑能力。

## 共同输入：固定一份可复现作品

先选定内容修订、程序版本、素材、语言、顺序、隐藏范围与所需 Reader。为该组合建立导出视图：关闭编辑控件，固定所需互动状态，等待字体、图片和页面布局完成，把动画停在有意义的最终状态。多语言分别形成快照；避免截图时混入浏览器旧草稿。

在大批输出前，选包含真实长文字、独立图片、复杂图表或背景效果的代表页转换，查看实际文件。导出限制影响设计时在此解决，不等全部完成才统一压成整页图。

## 可编辑 PPTX：对象为主，必要效果独立保留

1. **取得对象与布局。** 从制作数据模型获得内容、身份和类型；从已渲染页面取得实际文字样式、边界、图片裁切和层次。使用固定画布坐标系，避免缩放容器影响尺寸测量。仅靠 DOM 标签不能推断全部语义，Canvas／SVG 可结合原始数据与显式导出策略。
2. **映射到幻灯片坐标。** 选与画布相符的比例。画布宽 W、高 H，幻灯片宽 Sw、高 Sh，则对象位置与尺寸按 `x/W*Sw`、`y/H*Sh` 等转换；文字字号结合渲染尺寸、转换工具单位与实际字体度量校准，不能把 CSS px 原值当 pt。没有统一可靠的网页到 Office 自动换行保证。
3. **按对象生成。** 文字优先按段落／语义块建立原生文本框，保留必要富文本；独立照片／插画作为图片对象，保留可调位置、比例与裁切；简单线条和形状用原生对象；表格和图表在有原始结构／数据且工具支持时原生生成。
4. **单独处理复杂效果。** 无法可靠转换的渐变、混合、复杂 SVG 或交互可以渲染成独立图像／SVG 对象，并说明它能移动替换但内部不一定可编辑。背景可合成，但必须去掉已作为前景导出的文字和图片。隐藏对象以生成背景时保持布局，并保留层次依赖；不能简单让同一文字既在底图里又叠一个文本框。
5. **补充所需阅读材料。** 根据用途放备注、附录或另交 Reader PDF；讲者备注不自动成为完整细读版。交互参考下一节选择静态状态。
6. **检查两种结果。** 渲染／打开 PPTX 与 HTML 参考图比较；再实际编辑代表性文字、移动替换图片、修改所承诺的组件并重新查看。只有结构检查、没有可用 Office 查看环境时，明确哪些视觉和编辑行为未验证。

可用原生对象库（例如环境已有的 PptxGenJS、python-pptx 或演示工具）实现；按当前库说明核对能力，不要求安装指定库。按行拆框或文本叠底图可作为特定限制下的方法，但不能直接称为完整编辑体验。分离对象困难时先处理实际影响最大的部分，与用户明确剩余边界，不静默降低交付目标。

## 两种 PDF

**演示 PDF**：从固定画布的导出视图逐页生成，页面尺寸与画布一致，禁用网页导航和编辑 UI。可用浏览器打印或当前 PDF 工具；检查背景、字体嵌入／替代、页边与断页，不接受正文被打印成滚动网页碎片。

**细读 PDF**：从 Reader 的内容结构建立适合连续阅读的打印布局，包含必要解释、图片、图表状态、来源与页／章节关联。展开承担内容的折叠区域；长文、表格和注释按纸张分页。无需所有内容塞进 16:9，按钮与装饰控件不直接当正文输出。

## 把互动转成有意义的静态内容

| 原体验 | 可采用的静态表达 |
|---|---|
| 问题／情境选择 | 保留题干与选项，解析放后页／备注；是否展示答案由用途决定 |
| 筛选或比较图 | 选择能支持论点的状态，注明筛选条件；必要时并列多个状态 |
| 分步骤机制／模拟 | 关键步骤、参数与结果；不要只留初始空画面 |
| 原文、大图、画廊 | 核心图／摘录进入主体，其余按需要放附录与来源链接 |
| 音视频或真实在线收集 | 海报帧／必要文本摘要／访问入口；未发生的收集不编造结果 |

链接／二维码用于回到完整体验，不替代必须离线可懂的核心内容。

## 离线网页包

按相同版本把页面、脚本、样式、字体、图像、数据和所需媒体收进目录，资源用包内路径；允许分文件，不强求巨大的单 HTML。外部素材先核对是否可取得和分发，不能下载的部分说明或提供替代。

检查 `file://` 是否支持本项目模块／fetch 等使用方式；需要本地 HTTP 服务时提供清楚的启动方法及实际运行要求。只有单 HTML 可直接打开时才如此承诺。离线 Editor 按已选范围保存为本机状态或导出文件，云端鉴权、在线查询和收集按实际能力说明。

将包解压到新位置，用无缓存环境断网打开，检查媒体、Reader、语言、内部链接和本地交互；不要让服务工作线程或浏览器缓存掩盖缺失资源。附说明：打开方式、内容版本、离线可用范围、修改怎样保存、如何重新接续。

## 文件与维护记录

文件名区分用途、语言和版本，例如 `talk-r7-en-presentation.pdf`、`talk-r7-en-reader.pdf`、`talk-r7-en-editable.pptx`。名字只是便于人辨认，记录仍关联实际内容修订与程序／素材。用户无需获取所有格式；只交已选择且已生成验证的文件。参见 [交接示例](project-trace.md#轻量交接示例)。
