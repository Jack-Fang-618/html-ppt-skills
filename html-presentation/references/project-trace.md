# Project Trace

用轻量、可接续的记录维护当前依据与重要转折。命名是 Project Trace；形式不必是树，也不要求所有项目使用同一套文件。

## 何时和怎样维护

先查现有项目入口与记录。有合适记录则更新／连接，不另造互相冲突的状态来源。新项目在工作目录建立简短 `PROJECT_TRACE.md` 或等效索引，从初始理解持续更新，不等到最后重新整理全部聊天。

根据规模保留两种视角：

| 当前有效状态 | 重要演进 |
|---|---|
| 目的、使用者与必要条件 | 发生了什么实质改变及原因 |
| 当前阶段、版本与素材／脚本／样例入口 | 依据、用户确认或 agent 委托内判断 |
| 已选模式、语言、输出及实际能力边界 | 替代了哪一旧决定，影响哪些产物 |
| 用户保留的决定、已有授权、待评议事项 | 对反馈的处理及未采纳理由 |
| 未决问题、下一步、接续所需位置 | 内容／程序／素材版本与重要检查证据 |

条目可用稳定 ID 关联，但不要求每次改字开新记录。记录已确认、暂定、待验证、被替代和弃用的区别；用户要求、来源事实、agent 假设与实施证据不能混为一类。

以当前有效入口为先，再按需追溯历史。新说法不自动推翻更可靠的事实证据，已认可的表述也不是事实核验。出现冲突明确解决或保留待决，不让多个文件都声称“最新”。

丰富材料的项目在现有内容脚本中维护单元表达意图，Trace 只索引重要变化和理由，不另造一份重复大纲。反馈记录其意图、适用范围、已替代的旧判断和受影响部分，避免下轮再机械推广局部例子。重点有意改变要能追溯，普通措辞修订不逐次登记。

已有明确的用户偏好可在获授权的用户范围记录中复用，或随项目接续保留；不强制新增全局偏好文件。内容中立的技能不内置某人的浅底风格、品牌、页数、密码或学科。简繁联动／英文独立等有条件的通用能力在技能中说明，项目记录只写这次是否启用及例外。

重要决定变化后，原位更新文档顶部的当前状态，把被替代的状态留在演进记录中；不要仅在末尾追加另一段“当前有效”，却保留过时的顶部入口。交接前核对顶部的目标、阶段、产物入口和待决定事项是否仍然成立。

## 能力与检查的准确身份

写明是“计划实现”“代码存在”“本条件下实际验证”还是“未能验证”。保存接口存在不能代表云端草稿、权限和恢复都成立；格式校验通过不能证明用户编辑体验好。

必要检查记录实际对象、版本、条件、发现、修正及复查。无需逐次工具日志、全量对话或私有思考过程。公开 Reader 保持面向内容使用者，内部迁移／核验记录放在维护材料。

## 接续所需信息

让新 agent 找到源文件／代码、云端项目及授权方式、当前工作稿和发布版、关键来源／素材、构建输出方法、待办和恢复组合。只记录凭据如何安全取得，不记录凭据本身。

这份 Trace 属于具体作品。改进通用 skill 时，把实际任务中有效的判断另行提炼；不要把作品的某个品牌、页数、例子或用户偏好自动变成所有项目的默认规则。

## 轻量交接示例

项目较复杂时可把下面信息放在一个 `HANDOFF.md`，从 Trace 链接；小项目直接写在 Trace 中。不要求固定文件名，也不强制填写不存在的能力。

```text
当前给观众：release-7；正式地址；访问方式
当前工作稿：draft-12；待评议内容；编辑入口
本地独立修改：有／无；保存位置及共同基线
作品组合：内容修订 + 程序版本／commit + 素材快照 + schema
源文件与运行：根目录；实际预览／构建命令；输出目录
部署：平台／账号标识／项目 ID；仓库与生产分支或直接部署方式
状态接续：连接器或接口说明位置；环境；授权取得方式（无凭据）
导出：每份实际文件 → 内容修订／语言／隐藏范围／Reader／编辑程度
验证：何时在哪个版本上检查了什么；剩余限制
恢复：目标 release 的程序／内容／素材保存位置与恢复操作说明
下一步：当前待办；用户保留的决定；需重新核查的假设
```

恢复时先保存当前稿，重建指定历史组合，在候选环境检查后按已有授权建立新发布记录；浏览器修改过的云端状态不能只靠 Git 回退。换 agent 先读此索引再取得真实文件和远端状态，不凭“日期较新”选基线。

面向普通使用者另给短说明：去哪里看／怎么演示与阅读、从哪里编辑及保存发布、下载哪个文件、怎样要求继续修改或恢复。若旧 PDF／PPTX 未重新生成，明确标成旧版。程序、状态与素材的内部标识放维护索引，不塞到公开 Reader。
