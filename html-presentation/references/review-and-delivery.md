# 验收、交付与维护

按项目所选模式／格式读取对应部分，不要求每份作品生成所有输出或适配所有平台。

实际制作时按需读取 [部署路径](deployment-paths.md) 和 [多格式制作方法](export-methods.md)，不要只按下面的目标清单宣称完成。

## 目标驱动的成品检查

用当前成功定义检查真实成果，而非仅依代码结构或实现者自评：

- 连续演示：页的作用、精选依据、过渡、节奏和全场结论是否一致。
- 独立 Reader：无需讲者补充也能理解／操作；来源、核心媒体和展开内容可用；不混入开发日志与迁移说明。
- 实际呈现：必要观看尺寸、所选语言、真实图像、换行、对比、遮挡、动画和全屏；复杂页面实际查看。
- 交互／编辑：关键操作、键盘与焦点、退出回到主体、保存刷新、撤回与选定的隐藏范围；按能力变更检查接续。
- 输出与上线：打开实际文件和实际网址，不以构建完成代替验收。

变化决定检查范围：局部改字定点复查，共享样式、结构、语言或语义变更扩大到受影响部分。断链检查不能代替读总结，截图差异不能代替判断含义。已通过的无关测试不无限重复。

## 先还原任务，再评价成品

内容检查结合可用的原骨架、深入讨论、当前脚本和实际页面，不只对照某份文件。先判断本页是介绍、比较、论证、演练还是收束等，再评其完成情况；不要对并列介绍强加因果连接，或对开放讨论编造统一答案。

逐项辨认：重点是否漂移、必要前提是否缺失、解释是否只剩结论、材料是否归错页、关键内容是否藏得过深、原判断是否有理由修订。检查最显眼内容与默认路径，不能靠全文有某个关键词就判覆盖。漂移的具体判断见 [内容与协作](content-and-collaboration.md#本页任务与重点漂移)。

分两次读：Present 单独是否点明现场重点；Present 与 Reader 合起来是否承接必要推理。Reader 常显内容能否独立理解，可选展开是否提供新增价值。无需每页同样详细，也不要求把所有讨论常显。

同时看全场论证和承载量：局部点都保留不代表全场成立；字数减少不代表概念负担降低。检查关键区别是否被压平、实例是否有新增解释价值，以及总览、展开和跨段回扣是否相互支持。有 Narrative 时检查它是否说明组织关系，而不是重复页面或机械补过渡。

审阅意见不是新的绝对标准。建议须与页面任务、证据和最新用户决定相符；实质改变目的时明确处理。多位审阅者的数量不代替判断，保留有理由不采纳的建议。独立审阅只在授权允许时进行，不能从本参考自动获得委派权限。

## 验证真实使用序列

能力初建或变化时，按已选范围走实际路径，而非只有返回成功的单个函数：

| 能力 | 代表路径与观察重点 |
|---|---|
| 模式跟随 | Present 某页→对应 Reader→返回→另一页→Reader；每次定位当前页，而非第二次恢复旧页 |
| 现场延伸 | 开短例子／图注→阅读→关闭；不丢当前页，不自动把讲者送进长阅读模式 |
| 全屏 | 进入→前后翻页→展开→关闭→退出；栏隐藏后仍能操作，小屏／触屏按所选设备检查 |
| 编辑与语言 | 改字及布局→简繁联动／英文独立→撤回重做→保存刷新；既有人工润色仍保留 |
| 发布与角色 | 编辑者发布具体版本→全新观众会话读回→新编辑会话接续；观众不能写入，不误读本机草稿 |
| 浏览器鉴权 | 真实表单登录、错误状态、退出与资源访问；不只依赖手工构造请求头的接口测试 |
| 部署与接续 | 重建／部署→核对新程序及远端人工内容→新设备继续编辑；不把上线成功等同内容保存成功 |

只选与项目有关的路径，机制未变的局部改字不重跑全部链路。登录来源、会话策略等按真实浏览器行为定位原因，保留适当服务端校验，不通过撤掉权限保护修复体验。

记录检查究竟覆盖结构／DOM、真实浏览器渲染、手机视口、真实设备、投影还是受众理解。手机宽度模拟不等于真机验收，浏览器截图不等于投影试讲；未测条件写明，不能从其中一种推断其余已通过。

对完整成品或重大改版，在独立 agent 可用且允许委派时，用独立上下文检查同一目标、实际成品和原材料，不输入制作方“应该通过”的结论。要求位置、证据、影响、严重性及限制，允许无关键缺陷。制作方核实修正后复查。没有独立能力时标为单 agent 复查，不伪称独立审阅。

## 人类评议与自然反馈

交给用户可复现的候选版本、连续浏览入口，以及必要变化、实质限制和待判断事项。人判断意图、受众适配、专业与审美取舍；agent 先处理能自行发现的普通缺陷，并承担内容核查责任。

用户可以说标题、描述感觉、贴图或直接编辑；将反馈关联候选版本、稳定页／对象、模式／语言，保留“此处不要变”的决定。必要时分清缺陷、偏好和新增范围，不要求用户填工单。

修改前接续最新人工工作。修正后提供直接查看入口，说明实质差异和未解决问题；局部样例认可不自动变成全场认可。反馈与版本记录可很轻量，不需完整批注平台。

## 在线交付

根据目标网络、访问对象、分享期限、现有账号、所需动态能力选择托管。优先复用用户走通的环境；EdgeOne 与 Vercel 是候选，不能按地区强制单一路径或保证未经实测的可达性。

实现时读取当前适用工具／skill 与平台官方资料，区分账号首次配置、项目上线、后续更新。部署与访问授权按 [状态与发布](state-and-publishing.md) 处理；不默认购买域名，不复制平台时效政策到通用硬规则。

核对稳定项目地址与临时预览、所属账号和维护入口；检查页面、字体、媒体、Reader、鉴权及实际保存接口。目标网络无法测试时明确未验证；首页可达不能代表全部资源可用。

## PDF

普通演示 PDF 默认只输出主展示，不带 Reader／Editor 或应用导航。细读版是另行选择的交付，不因网页有 Reader 就自动要求生成。

演示 PDF 保留现场主画面及必要静态状态。细读 PDF 按自主阅读重排，关联相关页面、解释、来源和展开内容，不把丰富 Reader 硬塞进幻灯片比例。不需要 Reader 的项目不额外造一份空细读版。

导出后检查实际分页、换行、图像、字体和链接；浏览器看起来正常不能代替检查 PDF。

## PPTX

项目选择 PPTX 时提前明确编辑目标，并尽量保留文本、独立图片和有编辑价值的组件。使用当前可用的演示文稿工具／库；不假设本 skill 附有转换器。

从制作时保留对象身份、类型、内容／素材、几何、层次与适用映射。文字优先有意义的段落／语义块，图片保留独立对象及比例／裁切；受支持的形状、表格和图表映射为原生对象。标识有帮助，不能单凭 HTML 标签就保证任意 CSS、SVG 或 Canvas 全部原生转换。

不可可靠转换的复杂效果可以保留为独立视觉对象并说明限制，背景可以合成；可分离且需编辑的前景不随意压进底图，拆分后避免底图重复留下同一对象。图片可移动／替换、图内元素可编辑、数据可编辑是不同能力。

实际打开并修改代表性文本、图片和组件，再检查渲染。整页截图不能称为文字可编辑；文本叠底图不能称为全对象可编辑；按行分框要说明编辑舒适度。若达不到已约定的编辑目标，继续解决或与用户处理具体取舍，不能静默换成截图交差。

PPTX 默认只输出主展示，不带网页模式切换和 Editor。用户选择补充阅读时可用备注／附录或其他合适组织；备注存在不等于已形成独立细读体验。

## 交互的静态表达

保留交互承担的意义，按用途选择关键状态、步骤、结果、解释及网页入口。不一律删除、不只截初始状态，也不统一提前给答案；题目可与解析分开，不造标准答案或假统计结果。关键内容可独立理解，链接／二维码补充体验而非替代主证据。

## 离线网页

从明确快照打包程序、素材、字体、数据和必要启动方式，可自包含或文件夹加本地启动器。离线包不等于源码目录或单一 HTML。

验证断网时所需内容与本地交互，避免缓存掩盖远程依赖。外部链接、在线查询、云端保存、跨人实时收集按需要提供替代或明确不可用。离线修改先本地保存，后续导入／接续单独处理；页面密码不是文件加密，下载文件不继承站点权限。

## 版本和交接

每次输出采用指定草稿或发布组合，标明语言、隐藏范围、Reader 及互动处理。生成时间不代替内容版本；后续网页改动不自动更新旧文件。外部 PDF／PPTX 编辑若要成为新依据，另做显式比对接续，不承诺自动回写。

给团队简短版本索引：当前线上版本、待审工作版本、所选输出各对应什么。提供实际使用入口、微调／agent 修改方式和恢复入口；技术生成方法、程序／快照／素材关联留在维护索引，不塞入公开 Reader。

换设备／agent 通过当前 Trace 取得项目、权限通路和相关版本；Trace 不包含凭据，也不能代替实际文件和授权。若存在仅本机未同步工作，说明转移方法。可先由 agent 根据记录执行版本恢复，不要求在线版本中心。
