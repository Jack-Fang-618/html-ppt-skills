# 视觉参考工具箱

在选择视觉方向、图表、插画、信息图或交互细节时按需查阅。这里同时保留来源信息、agent 判断和人的取舍，帮助选择适用片段。资源入选候选目录不等于安装、认可全部规则或完成集成。

## 如何选择与维护

- 先看当前内容需要怎样被理解，以及使用者希望的气质，再选相关模块。人文、科研、科技、商业是可组合的检索线索，不给整个仓库贴唯一标签。
- 将**来源事实**、**agent 初评**、**策展者评价**、**实际试用记录**分开。初评不能冒充用户意见，官方预览也不能证明我们已经复现效果。
- 用户可自由口述“哪里打动我、哪里不喜欢、想在什么场合用”。保留关键原话及日期，再整理为可供 agent 使用的描述；代写的新增判断标为待本人确认。已明确说过的意见不用重复征询。
- 策展意见说明偏好及其理由，不把创作者个人品味强加给所有项目。实际任务中的用户目标、品牌、材料和观看条件优先。
- 收藏到仓库层面后，实际使用尽量定位到具体 skill、模板或风格。同一合集中的极简、水彩和工业风不能混成一种效果；多个来源先统一为本项目视觉方向。
- 分别标明只借鉴方法、适配模板代码、调用工具三种采用程度；后两者才需要进一步核查依赖、版本、许可、编辑及导出表现。相关规则见 [资源入口](resources.md)。
- 不默认通读或安装全部候选。先看相关预览和指引，用真实材料打样，再追加采用部分、局限及实际项目记录。星数帮助发现资源，不作为质量分或默认选用顺序。

## V01 · Lieflat Charts

**来源与入口：** [README／预览](https://github.com/larashero3-dotcom/lieflat-charts#preview)介绍 Lupi、Glance、Basics 三类图表表达；先看相关图型与 SKILL，再选模板。页面声明 PolyForm Noncommercial，采用代码或分发前按具体用途核对许可。

**Agent 初评：** 细线、留白与旁注的叙事方法值得考察。Lupi 可候选用于社会科学或人文数据的细读，Glance 可候选用于现场快速比较；这来自作者说明，尚未实际生成验证。高密度细节不宜原样塞进投影页。

**策展者评价（2026-09-28，依据用户口述整理）：** 认可作为工具箱组成部分。最打动人的是简约、好看、视觉舒服，同时数据表达清晰，是很有价值的工具包。用户原话：“视觉上是非常舒服的给人”“数据的表达也挺清晰的”。

**采用边界（同次反馈）：** 字号可能偏小，大面积留白虽有美学价值，却可能与具体演示页的内容需求冲突。一页中已经确定的文字、图片、图表要共同安排；图片承担氛围还是解释作用，也影响空间分配。不能为了遵循模板的留白，把这些表达压缩到难以阅读或放不下。按整页内容与密度调整布局，借鉴其视觉语言，不要求照搬空间比例。

**后续打样检查：** 用实际需要同时容纳文字、图片和图表的页面检查整体平衡与现场字号；单张图好看不能代替整页成立。此项是从反馈转成的验证建议，尚未实际测试。

## V02 · beautiful-html-templates

**来源与入口：** [画廊](https://github.com/zarazhangrui/beautiful-html-templates#gallery)、`index.json`、选中模板的文件。MIT；模板库并非完整的三模式产品框架。

**Agent 初评：** 本轮实际查看 Soft Editorial 与 Editorial Forest 的画廊截图：浅纸色、粉绿配色和衬线标题，能将数据页与文字页保持在同一视觉语言中。可候选用于希望温暖、克制而有编辑感的报告；字号、投影对比和中文字体仍要用真实内容验证。不是整库均属此风格。

**策展者评价（2026-09-28，依据用户口述整理）：** 认可它有版式变化，但担心仅参考 HTML 模板会过度约束创作，使页面单薄。与图像模型生成的案例相比，代码模板容易把关注点集中在字号、结构与清晰表达；用户希望兼顾视觉元素的交织、组合和完整构图，最终仍以 HTML 实现。这是对采用方式的要求，不是断言 HTML 本身无法实现丰富画面，也不是要求全部改成整页生成图片。

**采用边界：** 把模板作为可调整的排版和风格参考，允许围绕内容与素材重新构图。图片、图形、文字和背景的关系也应参与打样，不能默认只能填入模板预设区域。具体模板偏好尚未确定。

**补充视觉参照：** 用户提供 [free-ppt-template](https://github.com/ai-ppt-template/free-ppt-template) 进行比较。本轮查看咨询、绿色教育和科学课程的内页截图，作为整页图文编排的参考；其 README 说明使用图像模型整页渲染后包装 PPTX，未验证对象编辑性。这里只借鉴画面关系，不将其生成路径作为本项目默认实现。

## V07 · Baoyu 的插画、信息图与漫画模块

**来源与入口：** [文章插画](https://github.com/JimLiu/baoyu-skills/tree/main/skills/baoyu-article-illustrator)、[信息图](https://github.com/JimLiu/baoyu-skills/tree/main/skills/baoyu-infographic)，按叙事需要再看漫画模块。仓库 README 声明默认 MIT，其他分发及第三方资产按各自说明核对。

**Agent 初评：** 值得借鉴把信息结构与绘画风格分开选择的做法。人物故事、概念比喻可考察插画／漫画，知识关系可考察信息图。本轮看到的 [watercolor 样例](https://github.com/JimLiu/baoyu-skills/blob/main/screenshots/article-illustrator-styles/watercolor.webp)是暖纸底花卉水彩图，只能说明气质，不能证明研究图表达质量。生成图片中的文字和数值仍需核对，可编辑信息优先保留为独立对象。

**策展者评价（讨论后确认）：** 很多图像生成与风格表达能力可能已经被 GPT 图像模型内化，不必因此引入整套流程；但它对图片表达类型、风格等的整理仍有参考价值，能帮助人在打样时看见并比较选择。

**采用定位：** 作为视觉表达分类参考，借鉴 Type（信息结构，如流程、比较、时间线）、Style（绘画风格）和 Palette（配色）的区分。按当前内容提出有意义的候选，不变成必须逐项填写的问卷，也不让分类限制新的构图。SVG、位图、HTML／交互组件属于另一个实现层面的选择，由本项目的编辑、交互、清晰度与导出需求决定；不要误称文章插画模块本身提供 SVG 生成或选择机制。

**待实践的补充：** Agent 提出的素材提示词与参考记录可用于后续修改和交接，但尚未验证其相对现有流程的增益。本轮未安装整套工具、未生成图片，也未验证所有子模块。

## 继续补充人的判断

描述不要求写成评分表。可保留如下自然段结构：

> 我最喜欢的是……具体在这个样例里表现为……它适合……时使用，因为……；我不希望继承的是……。如果与另一种资源组合，我会取它的……。

Agent 再补入可定位样例、检索线索和采用边界。一个人的评价可同时包含赞赏和保留；“暂不收录”“只借鉴某个模块”“试过后不合适”也是有用记录。新增案例以实际体验为依据，不能自动给上述候选盖上“推荐／验证通过”的标签。
